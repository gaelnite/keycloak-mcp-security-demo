# Threat model

The application protects Keycloak realm data, the one permitted state change, and the
credentials that authorise each hop. The demo assumes a trusted Docker host,
operator, and private container network. The policies and fixtures target one
synthetic realm. [Security boundaries](SECURITY.md)

## Threats and verification

Unit tests establish how a verifier or handler responds to controlled inputs.
The live Docker checks establish what the configured Keycloak, SPIRE, MCP, and
gateway do together. The evidence column identifies that scope for each claim.

| Threat and profile | Control and enforcement point | Evidence | Remaining exposure |
| --- | --- | --- | --- |
| Stolen exchanged Admin token · delegated Docker | Keycloak configures a 45-second lifespan. MCP rejects a token lifetime over 60 seconds and requires the exact Admin audience, requester, capability scopes and role ceiling. The private gateway checks the bearer and route again. | Unit tests [`test_verified_distinct_token_and_projection` and `test_mismatched_or_overprivileged_token_stops_before_admin`](../tests/test_delegation.py). The [live delegation probe](../deploy/docker/delegation_probe.py) allows the right route and denies the wrong route and public Admin access. | A holder with access to the private listener can reuse a valid bearer on an allowed route until expiry. The desktop access token has a separate lifetime. |
| A compromised MCP process · delegated Docker | The gateway's route check is served by a separate container that holds no Workload API socket, executable or trust domain, so it can verify an exchanged token but cannot request one. If it is unreachable or confused, nginx forwards nothing. | [`test_the_mcp_process_does_not_host_the_check`, `test_the_sidecar_configuration_refuses_workload_credentials` and `test_a_configured_checker_cannot_exchange_even_if_asked`](../tests/test_admin_gateway.py), plus the live sidecar-stop check in the [delegated verifier](../scripts/verify-delegation.py). | MCP still builds the locale request body, and `auth_request` cannot carry a body, so a rewritten PUT would need MCP itself to be redirected rather than merely permitted. |
| Token issued for a different resource or actor · desktop Docker | The HTTP verifier checks issuer, signature, audience and expiry. MCP pins the session to the verified subject. Delegation checks that the exchanged token preserves the human subject. | Transport tests [`test_bad_audience_and_malformed_token_are_authentication_errors` and `test_a_different_subject_cannot_use_the_same_mcp_session`](../tests/test_mcp_transport.py). Exchange unit test [`test_mismatched_or_overprivileged_token_stops_before_admin`](../tests/test_delegation.py). | A valid token can outlive logout or a role change until it expires. |
| A user requests a tool or realm beyond their grant · desktop Docker | Keycloak filters eligible scopes. MCP checks the current grant and entitlement on each call, then Cedar evaluates the principal, tool and realm. The delegated gateway constrains method, path and query. | [`test_wrong_grant_stops_before_svid_or_network`](../tests/test_delegation.py), [`test_real_cross_realm_denied`](../tests/test_policies.py), and the [live delegated verifier](../scripts/verify-delegation.py) check denials alongside allowed reads with fixture data. | The policy relies on trusted realm role assignments and the configured tool-to-capability mapping. |
| Workload impersonation · headless and delegated Docker | SPIRE attests the node. Its agent identifies the workload by Unix UID and executable digest. Keycloak verifies the assertion against the trust bundle and binds the subject to its registered client. | The [headless live check](../deploy/docker/workload.py) rejects an expired assertion and accepts a renewed one. The [delegation probe](../deploy/docker/delegation_probe.py) denies assertions with the wrong audience or another capability's subject. | The runtime checks cover issued assertions and Keycloak binding. They do not establish isolation from a compromised host or an attacker controlling the registered process. |
| Policy or decision-log failure · configured MCP profiles | The policy enforcement point denies on evaluation errors, deadline, or inability to persist a configured audit record. The delegated profile logs redacted decisions. | Unit tests [`test_pdp_failure_fails_closed`, `test_audit_failure_fails_closed`, and `test_audit_record_has_no_arguments_and_mode_0600`](../tests/test_policies.py). [`test_timeout_denies_once_then_recovers`](../tests/test_policies.py) exercises a stalled worker. | A broken policy worker or log sink can make the service unavailable. Central retention and tamper resistance require additional controls. |
| Approval theft, tampering, or replay · delegated Docker | An independent operator signs the actor, audience, realm, action, tool, fixed fixture and locale. MCP consumes the approval ID in SQLite before dispatch. The configured approval lifetime is 90 seconds. | [`test_foreign_key_signature_denied` and `test_persistent_jti_store_serializes_competing_workers_and_reopening`](../tests/test_approval.py). The [live verifier](../scripts/verify-delegation.py) checks a fixture change and restore, different actor and target denials, and replay after MCP restarts. | An approval permits one attempt, including a failed attempt. Countering operator compromise and rollback of replay state needs separate controls. |
| Login-link issuance for an unintended user · archived legacy `magic_link_create` | The Docker registry excludes the tool. Legacy execution requires a configured extension and route, a permitted scope and policy, and approval for the concrete target. The handler sends the validated realm and user to the extension. | Legacy unit tests [`test_magic_link_crafted_realm_raises_before_post`](https://github.com/gaelnite/keycloak-mcp-security-demo/blob/archive/legacy-podman-26.8.1/tests/test_path_segments.py) and [`test_real_write_requires_enabled_and_approval`](https://github.com/gaelnite/keycloak-mcp-security-demo/blob/archive/legacy-podman-26.8.1/tests/test_policies.py) cover the invalid-path and write-policy boundaries. The [live delegated verifier](../scripts/verify-delegation.py) confirms the tool is absent from discovery and a direct call returns an unknown-tool error. | These tests cover MCP's decision and request boundary. Extension-side link lifetime and use depend on the installed extension. |
| Applying unintended configuration · archived legacy `config_cli_apply` | The Docker registry excludes the tool. The legacy gate checks the configured scope, Cedar policy and concrete realm-bound approval. The handler also requires `KC_CONFIG_CLI_APPLY=1` before running an operator-configured command. | Legacy unit tests [`test_config_cli_apply_target_is_the_callers_realm`](https://github.com/gaelnite/keycloak-mcp-security-demo/blob/archive/legacy-podman-26.8.1/tests/test_approval.py) and [`test_real_disabled_config_cli_extension_denied`](https://github.com/gaelnite/keycloak-mcp-security-demo/blob/archive/legacy-podman-26.8.1/tests/test_policies.py). The [live delegated verifier](../scripts/verify-delegation.py) checks discovery and direct-call denial. | Realm binding governs approval. The configured command and its credentials determine which resources it can actually change. |
